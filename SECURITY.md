# Security Policy

The team takes the security of this project seriously. We appreciate your efforts to responsibly disclose your findings, and we will make every effort to acknowledge your contributions.

## Supported Versions

Only the latest versions of our project receive security updates. Please ensure you are using a supported version to remain secure.

| Version | Supported          |
| :------ | :----------------- |
| 2.1.x   | :white_check_mark: |
| 2.0.x   | :x:                |
| < 2.0   | :x:                |


## 🛡️ Reporting a Vulnerability

**Please do NOT open a public issue for a security vulnerability.**

We use **[GitHub's private vulnerability reporting](https://github.com/uchamod/e-store-microservices-deploye/security/advisories/new)** feature to receive security reports. This ensures your findings are kept private and are addressed by the maintainers.

### **How to Submit a Report**

1.  Navigate to the "Security" tab of our repository.
2.  Click on "Report a vulnerability".
3.  Fill out the form with as much detail as possible.

### **What to Include in Your Report**

To help us resolve the issue quickly, please include the following:

-   A clear description of the vulnerability and its potential impact.
-   The version of the project affected.
-   Detailed, step-by-step instructions on how to reproduce the vulnerability.
-   Any proof-of-concept code, screenshots, or logs that demonstrate the issue.

## Disclosure Policy

Once we receive a security report, we are committed to the following process:

1.  **Acknowledgment:** We will acknowledge receipt of your report within **48 hours**.
2.  **Investigation:** We will investigate the issue to confirm the vulnerability and determine its scope. We will provide updates on our progress.
3.  **Resolution:** We will work to create a patch and release a new version of the project as quickly as possible.
4.  **Public Disclosure:** After the fix is released, we will coordinate with you to publish a security advisory that credits you for your discovery (if you wish to be credited).

We kindly ask that you do not disclose the vulnerability publicly until a fix has been released.
